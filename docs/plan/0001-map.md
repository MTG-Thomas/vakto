# Map: vakto

## Destination

A supervisor that turns a labeled work item into evidence — a claimed item, an
isolated agent run, and a pull request at full green — with no human keystrokes
in between, and with a tested single point of control for stopping it.

## Notes

- Contract and vocabulary: [ADR 0001](../adr/0001-supervisor-contract.md).
- Coordination lessons inherited from the predecessor project, and the triggers
  for adding queues, concurrency, or a durable runtime:
  [ADR 0003](../adr/0003-coordination-lessons.md).
- Board is truth for the work item; the ledger holds leases, dispatch attempts,
  and wake records. Neither replicates the other.
- Transport (durable HTTP hook + relay) is configuration, not the repo's code.
- First target is deliberately narrow: one repository, one lane, sequential.
- Six rules internalized from adjacent packages, and where each is proven:
  [ADR 0004](../adr/0004-internalized-rules.md).

| Rule                                                             | Proven in      |
| ---------------------------------------------------------------- | -------------- |
| 1. The wake carries no work content                              | slice 0        |
| 2. Wakes are suppressed and budgeted                             | slice 0        |
| 3. Reconcile only for what the last look did not see             | slice 0        |
| 4. No silent board write; budgets charge live work               | slice 1        |
| 5. Stop is two verbs; resuming reports what it measured          | slices 2 and 5 |
| 6. Authority scoped by the channel; no reachability on the board | slices 0 and 5 |

## Decisions so far

- Board owns work state; no second tracker.
- Trigger is a work-lifecycle event (label), not a board field change.
- Reconcile-from-board on every wake; idempotency keys describe work, not
  deliveries.
- Claims are leases with an expiry.
- Authority includes opening pull requests and driving them to full green; it
  never includes merging.
- One plug to pull, tested in slice 0.

## Not yet specified

- Concurrency: how many lanes, and how a lane is isolated (worktree per item is
  the working assumption).
- What "full green" means per repository, and where that policy is stored.
- How a lane reports partial progress and cost.
- Whether the ledger is SQLite, an embedded log, or something the host already
  provides.
- How the supervisor is upgraded while leases are live.

## Out of scope

- Merging anything.
- Multi-tenant operation, or any customer-facing traffic.
- Replacing the human's ability to work an item by hand at any moment.
- A second work tracker, or any tracker that must be mirrored.

## Slices

### Slice 0: wake path proven, with a tested kill switch

Scope: transport wired to a no-op supervisor turn. No board writes.
Acceptance criteria: a probe returns the host's own not-found verdict; a labeled
item returns an accepted acknowledgement; the same payload delivered twice is
shown to start two turns (the dedupe requirement is demonstrated, not assumed);
all three stop methods are documented and verified — disable the trigger, revoke
the transport credential, stop the host.
Measured, not assumed: the wake prompt is the fixed template with no payload
field interpolated into it (rule 1); a parked item, a reconnect carrying nothing
new, an empty queue, and an already-announced unacknowledged item each produce no
wake, while a busy lane is re-checked on settle instead of having wakes stacked
behind it (rule 2); a reconcile pass wakes only for work the previous pass did
not see (rule 3); a wake arriving through the transport proves it cannot author
or redefine work, and the board carries no endpoint or credential material
(rule 6).
Verification: transport probe response, delivery log, ledger rows for both
deliveries, and one test per rule above.
Depends on: nothing.
Stop/expand gate: stop if two deliveries cannot be distinguished at the
supervisor — that changes the identity design, so revisit ADR 0001 first.

### Slice 1: reconcile and claim

Scope: wake → read labeled items → idempotent claim with a lease → ensure the
item is on the board → move it to in-progress → comment with the delivery id and
the reason → one standup line.
Acceptance criteria: replaying the same delivery yields one claim and one no-op;
a card moved by a human mid-run is not stomped; an expired lease is re-claimable
after a simulated crash.
Verification: replay the identical payload twice; inspect board, ledger, and
comments; unit tests over `planReconcile`.
Depends on: slice 0.
Stop/expand gate: stop if board writes are not idempotent under replay.

### Slice 2: dispatch to full green

Scope: one repository, one lane, sequential. Claimed item → isolated workspace
(branch + worktree, dirty trees preserved rather than reset) → agent run under
the repository's gates → pull request opened ready for review → required checks
driven to green → failures produce a needs-you state with the diagnosis instead
of silence.

Dispatch carries an explicit lifecycle, adopted from the predecessor project:
`queued → dispatching → submitted → uncertain → acknowledged → completed`, with
a request id for idempotent replay and a separate receipt that holds the
acknowledgement evidence. An `uncertain` submission is inspected before it is
resent, and is never retried blindly; already-acknowledged work is never
submitted twice.

Acceptance criteria: a labeled item ends as a ready-for-review pull request with
all required checks green and no human keystrokes in between; a simulated crash
between submission and recording leaves the dispatch `uncertain` rather than
either silently succeeded or silently retried; a dirty worktree is reported and
left intact.
Verification: pull request URL, check suite result, board status, ledger
attempts and receipts; a kill-and-restart of the lane.
Depends on: slice 1.
Stop/expand gate: stop before concurrency. One lane until this is boring.

### Slice 3: durability and restart proof

Scope: kill the supervisor or its host mid-run, then restart within the
transport's retention window.
Acceptance criteria: no duplicated tool effects; the held delivery replays and
reconciles exactly once; exactly one lease exists per item; the board is
consistent and readable throughout.
Verification: stop the host, deliver a wake, restart, then inspect ledger,
board, and pull request.
Depends on: slice 2.
Stop/expand gate: if resume duplicates effects, do not adopt a durable runtime;
keep supervised, resumable-by-human runs instead.

### Slice 4: standup and review handoff

Scope: one board comment per cycle, one message into the human's thread, and
review/needs-you columns that link the pull request and the failing check.
Depends on: slice 3.

### Slice 5: stale work and takeover

Scope: identify stale leases and dead lanes without acting on them; report what
was found and release only on an explicit instruction. A human who works an item
by hand — moving the card, commenting, editing the branch — must be able to
take it over at any point without the supervisor fighting them.
Acceptance criteria: a lease past its expiry is reported and re-claimable; a
human-taken item is never re-claimed while the human is visibly active; no
cleanup happens automatically; the ledger and board agree about who owns the
item after a takeover.
Verification: simulated stale lease, simulated human edit, then the supervisor's
next reconcile; ledger and board readback.
Depends on: slice 2.
Stop/expand gate: stop if takeover requires deleting or rewriting evidence.
The two stop verbs must be distinguishable here: disabling the trigger leaves an
in-flight run alone, stopping cancels it at a safe checkpoint and leaves the item
resumable with no evidence claimed (rule 5).
